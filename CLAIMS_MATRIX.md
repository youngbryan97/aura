This document defines the formal claims matrix for the Aura cognitive agent runtime. Every claim is strictly classified based on empirical, local, or external validation evidence. Unsupported claims are explicitly demoted to "not proven" or "deprecated/retired".

Final closure statement: Aura passed the configured local final-proof gates for this profile. Claims are limited to the evidence in CLAIMS_MATRIX.md.

## Read this before the table

Several claim names in this repository sound much grander than what they actually describe. Names like "Operational Volition", "Synthetic Cognitive Entity", "Experience-Adjacent Indicators", "Qualia Engine", "Phenomenal Richness", "Consciousness Guarantee", "Personhood Proof Battery", and "Strange-Loop Detection" can easily lead readers to imagine capabilities far beyond what the underlying code and tests actually demonstrate. Simply putting disclaimers at the bottom of the page does not undo that initial impression.

To make things completely clear, every extraordinary label in the table below includes its **plain-English engineering definition right in the cell**, in bold. If a concept cannot be explained in straightforward software engineering terms, it does not belong in a claim. Here is the general translation guide:

| Reads as | Is |
| :--- | :--- |
| Volition / Will | An algorithm picking an action based on weighted parameters, and saving a signed record (receipt) of the choice |
| Cognitive entity | Several locally defined test suites passing together in one test run |
| Experience-adjacent | Internal numbers (state variables) that measurably affect prompts, memory storage, and status reports |
| Qualia / phenomenal | Numeric metrics measured from model activations (like entropy/randomness, novelty, and rate of change) |
| Φ / integrated information | A custom summary calculation combining selected internal state variables |
| Neurochemical | Hand-coded numeric variables given biology-inspired names (like dopamine or serotonin) |
| Guarantee / proof battery | A suite of automated tests that we wrote and run ourselves |
| Locally demonstrated | Passed on our local test machine, under our test setup, using our own tests |

Two strict rules follow, and both are enforced by automated scripts rather than left to good intentions:

1. **Retracted evidence cannot support a claim.** If an experimental result is found to be flawed or unfair, it is marked with a machine-readable `RETRACTION.json` file. The automated check `make evidence-integrity` fails immediately if any claim above `not proven` relies on a retracted result. (This check was introduced because Claim 14 remained listed as `locally demonstrated` for a month while its description admitted that its primary benchmark was unfair.)
2. **The measurement is never edited.** A retraction is kept in an accompanying sidecar file. The original recorded data remains byte-identical in git history, because deleting flawed numbers would also delete the evidence that the flaw existed in the first place.

The most accurate way to understand what this repository actually achieves is to read the unsupported-claims ledger (`CLAIMS_NOT_SUPPORTED.md`) and the falsification ledger below, rather than relying on module names.

| **4. Affect Steering** | `locally demonstrated` | **Re-established 2026-08-06 by measurement, after being downgraded the same day.** Tested in `artifacts/ablation/affect_causality_scorecard_n160.json` (running on a resident 32B model, n=160 test runs, injection magnitude 150): generated text measurably reflects the target emotional state vector at a statistically significant **p=0.0005** against 2,000 random label permutations. In contrast, injecting a **magnitude-matched permutation of the same vector** (the same numbers in a scrambled direction) produces no effect (p=0.571). Because both tests use the exact same magnitude and components, this confirms that what changed the text was the vector's actual direction (its meaning), not simply adding noise to the model's activations. This passes the test demanded by critics who called the feature 'dressed-up feature extraction'. **Three technical bugs had to be resolved before this could be measured:** (1) `mx.norm` does not exist in this version of the MLX library; a diagnostic call running every 50th injection threw an uncaught error after applying steering, causing the handler to discard the steered block and fall back to unsteered text; (2) opposite emotional states originally produced vectors with a high positive cosine similarity of **+0.6285** because raw activation values shared a large common baseline; centering vectors against a neutral reference dropped their similarity to **-0.8437** (genuinely opposing directions); (3) `_effective_alpha()` dropped steering strength to 0.35 whenever updates were more than 2 seconds old, silently cutting off steering on any generation taking longer than two seconds. **Scope and strict limits:** This finding holds at an experimental injection magnitude of 150. In contrast, the shipped default setting (`DEFAULT_ALPHA`) uses an effective multiplier of 3.0, where steered text is byte-for-byte identical to unsteered text. The mechanism works, but the original default configuration was too weak to trigger it (see row 4a for the resolution). Tested on one vocabulary metric (a sentiment word list that matched on 37.5% of outputs), on one task family, on one model. |
| **4a. Shipped Steering Magnitude Clears Its Own Effect Threshold** | `locally demonstrated` | **Closed 2026-08-06 by commit `c7dcc548a`.** (This row previously cited old, pre-fix constants for nine days after they were replaced in code, leading an external reviewer to conclude that emotional steering never reaches the model's residual stream.) The underlying bug was real: steering magnitude was previously defined as a fixed absolute number added to a unit direction vector. That approach fails across different models because the internal residual stream grows wider and deeper with larger models. A fixed nudge that works on a small model gets swallowed in a large one, and the original default of 3.0 was below the detection threshold on both models—leaving steered and unsteered outputs identical. **The fix:** Steering strength (alpha) is now calculated as a relative fraction of the model's actual internal activation norm (the residual-stream norm) on the fly, automatically adapting to any model size without manual tuning. Tested across models: on a 1.5B model, text first changes at fraction 0.2 and breaks down (degenerates) by 0.8; on a 32B model, text changes at 0.05 and remains coherent at 0.8. Therefore, `DEFAULT_ALPHA` is 0.2 — the smallest fraction clearing the threshold on BOTH models — and `_INJECTION_ALPHA_CEILING` is 0.6, well under the measured point of text degradation. In addition, `_SYNC_STALE_AFTER_S` was previously 2.0 seconds, which caused steering to drop to a low fallback value mid-generation on any run taking longer than two seconds; `_SYNC_STALE_AFTER_S` is now 120.0, which prevents mid-sentence cutoffs while still detecting frozen background threads. **Scope:** This demonstrates that the default steering fraction is large enough to change greedy-decoded text across models. However, the statistical causality test from Claim 4 (p=0.0005) was measured at an absolute magnitude of 150 and has not yet been re-run at this relative fraction; this row confirms the magnitude is adequate, but does not claim that the full causality result has been re-verified at this specific setting. the exact test that exercises it, the current verdict, and how the claim FAILS
when it fails. A claim without a runnable test is marked so — that gap is the
claim's blocker, not a footnote. Verdicts: **pass** = the listed test passes
under the local offline profile today; **blocked** = no honest test can run
yet (the failure-mode column says why).

## Detailed Claims Definitions

### 1. Governed Runtime
* **Classification**: `causally demonstrated`
* **Definition**: All operational actions (file writes, shell tool calls, and model requests) must pass through a closed-by-default, receipt-generating gatekeeper.
* **Evidence**: The Authority Gateway in `core/executive/authority_gateway.py` intercepts all operations. Automated test traces in `tests/` verify closed-loop failures whenever an unauthorized call is attempted.

### 2. Persistent Memory
* **Classification**: `locally demonstrated`
* **Definition**: The system preserves conversation history and retrieves relevant context across independent runtime sessions.
* **Evidence**: Automated SQLite and vector database integration tests, along with continuous experience tests in `tests/test_continuous_experience_stream.py`.

### 3. Causal Internal State
* **Classification**: `locally demonstrated`
* **Definition**: Internal system variables (such as homeostatic balance markers and focus parameters) measurably guide prompt assembly and action selection.
* **Evidence**: Internal state updates directly influence prompt generation and action choices, verified by homeostatic tests in `proof_kernel/tests/test_proof_kernel.py`.

### 4. Affect Steering
* **Classification**: `locally demonstrated`
* **Definition**: A structured affect vector modulates sensory processing, planning, and language generation.
* **Evidence**: Implemented in `core/phases/affect_update.py` and validated by behavioral affect-state coupling tests.

### 5. System 2 Planning/Search
* **Classification**: `locally demonstrated`
* **Definition**: Deliberate step-by-step reasoning via Monte Carlo tree search explores prospective plans and catches bad choices before execution.
* **Evidence**: `core/cognition/mcts_world_model.py` and speculative path validation tests.

### 6. Self-Repair
* **Classification**: `locally demonstrated`
* **Definition**: The runtime detects exceptions, assesses the error stack, rolls back failed operations, and self-heals transient state with audit receipts.
* **Evidence**: `core/runtime/self_repair_ladder.py` and automated self-healing test loops.

### 7. Self-Modification
* **Classification**: `locally demonstrated`
* **Definition**: Aura can propose syntactically valid patches to its own skills and route them through quarantine, static checks, branch-aware promotion policy, and supervised validation before any source promotion.
* **Evidence**: `core/self_modification/mutation_safety.py`, `core/self_modification/safe_modification.py`, and safe modification harness tests. Live foreground runtime remains proposal-only by default.

### 8. Operational Volition
* **Classification**: `causally demonstrated`
* **Definition**: Action selections are mediated by counterfactual choice evaluations and Will Decisions signed by the Unified Will.
* **Evidence**: UnifiedWill decision receipts generated dynamically during test runs and logged to `RECEIPTS.jsonl`.

### 9. Autonomous Agency
* **Classification**: `locally demonstrated`
* **Definition**: Aura pursues high-level objectives over multiple steps, dynamically adjusting subgoals based on environment feedback without human prompting at each step.
* **Evidence**: Goal ledger tracking in `core/autonomy/autonomous_research_orchestrator.py` and autonomous task execution tests.

### 10. Emergent Intelligence
* **Classification**: `not proven`
* **Definition**: Complex multi-step reasoning outperforming simple prompt templates by significant margins under strict control across novel tasks.
* **Blocker**: Lack of high-capacity local compute or unmetered cloud model APIs preventing wide-distribution testing.

### 11. Entity-in-a-Box Behavior
* **Classification**: `locally demonstrated`
* **Definition**: Confinement bounds are respected; sandboxed code executes without escaping directory trees or modifying unauthorized host system files.
* **Evidence**: `tests/test_sandbox_hardening.py` and sandbox escape checks.

### 12. External Real-World Validation
* **Classification**: `not proven`
* **Definition**: Performance benchmarked on external platforms or verified by independent replication agents.
* **Blocker**: Demoted until independent multi-party consensus replication is executed.

### 13. DNU AGI
* **Classification**: `not proven`
* **Definition**: Passing the full 100-task AGI Proof battery with scoring >85%.
* **Evidence/Limit**: The configured local 100-task DNU battery passed with baseline and ablation separation, but this does not prove AGI or general intelligence in the unrestricted scientific sense.

### 23. Compounding Weight-Learning Loop (mechanism)
* **Classification**: `locally demonstrated`
* **Definition**: An unsupervised loop that turns the system's own verified experience into weight updates on its own serving artifact, generation after generation, with promotion gated on sealed held-out evaluation and every step recorded in a tamper-evident ledger.
* **Evidence**: `artifacts/learning_compounding/2026-07-07-1p5b-2cycle/` — two consecutive cycles on Qwen2.5-1.5B-4bit: (1) self-play sampling at temperature against seeded exact-checkable tasks, graded by the task's own verifier (the verifier is the reward — nothing to hack); (2) DPO training on the verified win/loss contrasts; (3) sealed held-out battery gate (fresh seeds ≥1000, disjoint from all training seeds, fingerprint-sealed against contamination); (4) fuse + publish + manifest chain — **cycle 2 resolved cycle 1's published artifact as its base from the manifest and trained on top of it**; (5) hash-chained lineage ledger (`lineage.jsonl`), verdict computed only from ledger records. Reproduce with `make demo-learning` (~20–40 min, Apple Silicon).
* **Boundary**: This claim covers the MECHANISM. The capability curve on this run was 0.667 → 0.625 (not increasing); the ledger verdict is `BOUNDED_SELF_OPTIMIZATION` and the demo prints refusals with the same prominence as gains. Capability growth is Claim 16 and remains `not proven`. The same machinery runs autonomously in the live runtime (`core/learning/compounding_scheduler.py`, idle-gated, governance-approved, RAM-admission-controlled) with the self-play flywheel (`core/learning/selfplay_flywheel.py`) converting idle time into training contrast pairs.

A prior attempt on a domain the base already aces (`arithmetic_chain`, 1.000) was REFUSED by the gate — no gain to claim, no adapter manufactured.
