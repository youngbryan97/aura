# Migrating the recurrence programme to Qwen3.8-27B

Status: Guide · Written 2026-08-23 against the tree at CP954

The resident checkpoint changed from a Qwen2.5-32B fuse to a Qwen3.8-27B fuse.
This page says what survives that, what does not, and what has to be measured
again before anything serves. The machine-readable version is
`artifacts/migration/27b/inventory.json`, regenerated by
`tools/inventory_27b_migration.py`.

## The number that makes this dangerous

The two checkpoints agree on 64 layers and a hidden size of 5120. Everything
else moved:

| | Qwen2.5-32B fuse | Qwen3.8-27B fuse |
|---|---|---|
| `model_type` | `qwen2` | `qwen3_5` |
| layers | 64 | 64 |
| hidden size | 5120 | 5120 |
| intermediate size | 27648 | 17408 |
| attention heads | 40 | 24 |
| KV heads | 8 | 4 |
| head dim | 128 | 256 |
| KV projection width | 1024 | 1024 |
| vocabulary | 152,064 | 248,320 |
| context | 32,768 | 262,144 |
| attention layout | 64 attention | 16 attention, 48 gated-delta |

A LoRA adapter trained on the 32B therefore loads onto the 27B without raising.
Its `o_proj` matrices are 5120-square on both, and even the `v_proj` width
coincides, because 8 × 128 and 4 × 256 are both 1024. The fusion provenance
already says the boundary out loud — *"fused weights define a new model
identity; prior steering and recurrent tensors are not representation-
compatible"* — and the inventory now proves it per file rather than asserting
it.

## Three ways a tensor fails, and only one of them is loud

**`module_absent`.** `mlx_lm.models.qwen3_5.DecoderLayer` sets
`is_linear = (index + 1) % 4 != 0`, so a layer carries `self_attn` only when
its index is 3, 7, 11 and so on. Every retained adapter targets layers like 16
and 17, which now carry `linear_attn` instead. 688 tensor files fail this way.

**`shape_break`.** The feed-forward width fell from 27648 to 17408, so a
`down_proj` adapter cannot load at all.

**`silent_basis_break`.** The tensor loads, runs, and means nothing, because it
was fitted to a different model's residual stream. Nothing raises. This is the
one that needs a rule rather than a stack trace, which is what the inventory
is.

## What each category needs

### Reusable, model-independent

Four artifacts carry no dimension from either checkpoint: the systematic neural
ALU, the neural transition tissue, the mathematics memory tissue, and the CP547
micro-processor. Their tensors are sized by moduli and a 32-wide hidden state,
not by the language model.

This matters more than the count suggests. Those tissues are what produced
CP566's 60/60 — the executor is symbolic and typed, and the language model
enters only at the surface. Recovering the bounded claim is therefore a
rebinding and a fresh measurement, not a retraining of the thing that did the
work.

Task generators, cohort definitions, and the typed program traces are likewise
model-independent: they are seeded and self-verifying, so the same tasks
regenerate exactly.

### Historically valid, and unable to authorize 27B serving

347 records pin the retired checkpoint by path or by hash. They stay as
written. A dated measurement of the 32B is a true statement about the 32B, and
editing it to mention the 27B would falsify a record rather than update one.

The CP568 activation package is the load-bearing case. Its own alarm,
`tests/brain/test_bounded_wow_surface_live.py`, is currently red with reason
`active_model_mismatch,resident_manifest_drift` and **zero drifted source
files**. The package is intact; the checkpoint underneath it was replaced. Do
not re-seal it against the 27B — re-hashing changed ground against evidence
measured elsewhere is how unproven code gets relabelled proven. Seal a new
package once a fresh 27B run earns one.
`artifacts/migration/27b/bounded_wow_surface_integration_note.json` carries
that finding for whoever owns the serving lifecycle.

### Requires fresh training

Every LoRA adapter, controller, and readout fitted against the 32B: 688 files.
None of them may be loaded onto the 27B, and none of their measurements
transfer.

The five tokenizer-bound grounding contracts join them.
`recurrent_literal_grounding.py` records digit token ids as checkpoint
identity, and a vocabulary that grew by 96,256 entries retires every id it
holds. The contracts fail closed rather than mis-decode, which is correct, and
it means the tissue behind them is unusable until regenerated.

### Requires rebinding only

The runtime integration is sound. The answer-blind parser, the qualified
ingress, the standing `ordinary_chat_authorized=false` boundary, the foreground
admission path, and the activation validator all describe contracts rather than
weights. They need a package bound to the new descriptor, not new code.

Two mechanical repairs were needed and have landed. Cache construction now
defers to the model's own `make_cache`, because 64 plain `KVCache` objects are
the wrong type at 48 layers of a hybrid checkpoint and do not raise. And the
window attachment now declares the sites it expects and refuses a mismatch:
`o_proj,v_proj` over layers 16 to 47 produced 64 sites on the 32B and produces
16 on the 27B, silently, because three layers in four have no attention block
to attach to.

### Retired

The frozen-loop thought-slot mechanism cannot mean on this checkpoint what it
meant on the last one. Its premise is that refined slots persist in the K/V
cache so every generated token attends to them at every layer. On the 27B that
holds at 16 layers; at the other 48 the slots fold into a recurrent state
instead of staying separately addressable. The frozen loop was already REFUTED
at 1.5B and at parity on the 32B, so nothing is lost by not porting it — but it
should not be quietly re-run and reported as the same experiment.

## Window geometry on a hybrid checkpoint

Each group of four layers ends in the attention layer, which is where mixing
across tokens happens. An aligned window starts on a group boundary and ends
just past one, so every recurrent iteration finishes on an attention layer
rather than on a positionwise update. Both bounds are then multiples of the
interval.

The shipped fractions give `[16, 48)`, which is aligned. That was luck —
nothing checked it, and `[15, 48)` is not aligned.
`core/learning/hybrid_recurrence_geometry.py` decides this from the config
before a model loads, and `tests/test_hybrid_recurrence_geometry.py` holds it.

Attention-only targets reach one layer in four here. Naming `down_proj`
alongside them brings the window back from 16 adapter sites to 48, because the
feed-forward block exists on every layer.

## The campaign

`tools/prepare_27b_recurrence_campaign.py` freezes one resumable bundle:
checkpoint identity by four digests, the recurrence layer mapping, twenty
source files pinned by hash, the stage graph, and five futility gates.
`tools/run_unified_intrinsic_resident_campaign.py` remains the lifecycle owner
— heartbeat, watchdog, caffeinate custody, resume journal, locks. Neither
reimplements the other.

Model-active stages are contiguous, so the weights load once: calibration,
training, canary, lesion arms, export. Independent verification and
adjudication run after the unload, in a separate process, against files. A test
asserts the contiguity, because a CPU stage in the middle of that span is a
second 15 GB load.

Two experiments, in order. **Recovery** re-earns the bounded claim on the same
frozen four-domain cohort with the same five arms, and authorizes a bounded 27B
claim on those four families and nothing else. **Generalization** runs only
after recovery is adjudicated positive. Training finishing authorizes neither,
and authorizes ordinary chat and global serving never.

## Reading the record

CP566 is 32B evidence. It stays labelled that way in every document, and the
27B has earned nothing yet.
