# Aura's variables and measurements explained

Status: Guide · Definitions updated 2026-10-25

A variable is a value the software stores or calculates. A useful definition says what the value represents, what reads it and what changes because of it. Units, scope and missing values belong beside the number.

The examples here explain meanings; they are not additional measured Aura results. For numerical ISC arithmetic, use [the worked ISC guide](ISC_VARIABLES.md). For the overall project, use [the plain-English tour](PLAIN_ENGLISH_GUIDE.md).

## Getting started

Aura is a local AI research system built around a language model, persistent records and software that manages actions and ongoing work.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Model lane | A route to a particular model or model service | The route can change resource needs and what answers a request | A smaller configured lane may answer while a larger one is unavailable |
| Ready | The declared startup requirements have been met | Allows work to enter that route | A process can be running before its model is ready |
| Configuration | Settings read by the program | Only a setting with a reader can change behavior | An invented environment variable changes nothing |

## Conversation

Conversation support turns a request into a reply and, when enabled, into speech. Streaming lets delivery begin before every later stage finishes.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Turn | One request and its associated processing | Binds work to the person who asked | An interrupted turn must not publish into the next turn |
| Time to first audio | Elapsed time until audible output starts | Describes how immediate speech feels | Fast text generation can still be followed by slow speech synthesis |
| Token | A unit processed or generated by the language model | Affects context capacity and decoding cost | A word can use more than one token |
| Playback drain | Time needed to finish audio already queued | Separates generation time from what the listener hears | The model may be finished while speech is still playing |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#conversation) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#interaction)

## Models

The language model supplies text generation. Steering changes selected internal calculations using a measured direction and a controlled strength.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Weights | Stored model parameters | Usually define the trained model | Changing an activation is not automatically retraining the weights |
| Activation | A value computed inside a forward pass | Can carry an intervention into generation | A change at one layer may have a different effect from the same change elsewhere |
| Steering vector | A direction added to selected activations | Defines which internal change is applied | Its identity and placement must match the certificate |
| Steering alpha | The coefficient controlling that addition | Sets an implementation-specific intervention strength | Alpha 0.5 is not 50 percent emotion |
| Certificate | A record of a measured basis under a stated protocol | Binds a channel claim to its tested conditions | A channel certificate can pass while installation is refused |
| Parameter count, such as 27B | The approximate number of stored model parameters; B means billion | Describes model size, not an intelligence or consciousness score | A 27B model can have different memory needs under different numeric formats |
| Quantization | Storing or computing numbers with reduced precision | Can reduce model memory and change quality or speed | A lower bit count does not guarantee the best practical result |
| Context window | The token budget available to a model request | Limits how much text fits at once | A memory store can be larger than the material placed in one request |
| Sampling temperature | A setting affecting the distribution used to choose tokens | Can alter variability in generated text | It is different from the computer’s physical temperature |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#models) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#steering)

## Memory

Memory keeps records beyond the immediate request and selects relevant records for the current turn.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Working memory | Information currently kept available | Shapes the next computation | A retrieved note can be available for this turn without being permanent context |
| Embedding | A numerical representation used for similarity search | Helps find related material | Similar wording and similar meaning can produce different retrieval behavior |
| Retrieval score | The ranking produced by a particular search method | Orders candidates for recall | It is not a probability that the record is true |
| Provenance | Where a record came from and how it changed | Lets a reader assess and correct it | An observation and an inference should retain different sources |
| Retention | Rules for keeping or deleting records | Controls continuity, storage and privacy | Deleting a source should have defined consequences for derived records |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#memory) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#memory)

## Affect

Aura uses internal variables for positive or negative condition, activation, needs and operating strain. Their role is established by what they change.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Valence | An internal positive/negative coordinate | Can influence retrieval, attention or reports | A reported rating must follow an intervention to count as grounded |
| Arousal | An internal activation or intensity coordinate | Can change the strength or urgency of processing | It is separate from whether a condition is positive or negative |
| Drive | A represented need or motivation | Contributes to proposed work or choices | A curiosity value should change a relevant choice to support a causal claim |
| Baseline | A recorded reference level | Makes a change interpretable relative to ordinary state | Above usual and below usual need an actual reference |
| Momentum | How a state carries forward while new input arrives | Controls persistence and settling | A value overwritten immediately cannot carry a sustained intervention |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#affect) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#affect)

## Attention

Several concerns can propose work, but attention selects what has influence now and makes selected information available elsewhere.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Candidate | A proposed item for attention | Enters a competition | A memory and an intention can have different content types |
| Salience | A contribution to how much an item stands out | Can change its chance of being selected | An urgent observation can outrank a routine item |
| Workspace | The selected information and competition state | Makes information available to other components | A selected item can influence several readers |
| Impasse | A decision that lacks a justified winner | Creates a reason for further work | An exact tie should not be disguised as a meaningful preference |

## Reasoning

The reasoning programmes investigate whether extra computation or learned internal representations improve answers on tasks not used to choose the method.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Depth | Additional stages or repeated computation | Trades time and resources for a possible reasoning benefit | A deeper pass still needs a measured correct-answer gain |
| Latent state | Internal numerical representation rather than generated words | Can carry computation without printing each step | A latent operation needs evidence that its output affects the answer |
| Held-out task | A task excluded from fitting or method selection | Checks transfer beyond the development examples | Success on a new task is stronger than replaying a fitted example |
| Verifier | A mechanism checking a stated property of a result | Can prevent unsupported answers from being accepted | Its own false acceptances and false rejections also need measurement |

## Learning

Learning changes later behavior using earlier outcomes. A kept procedure is executable work retained for reuse under a defined checking rule.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Procedure | Executable steps retained for a class of problems | Can replace repeated derivation | A solver may be kept only after matching required known answers |
| Training set | Examples used to fit a method | Shapes what the method learns | It cannot also supply the whole independent transfer claim |
| Validation | Checks used to decide whether a change is acceptable | Can reject a harmful update | A passing local check may still have a narrow scope |
| Expected value | Expected benefit minus relevant cost | Can decide whether a retained rule pays for itself | A rule that saves 5 units but costs 7 is not beneficial on that accounting |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#learning) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#learning)

## Agency

Agency concerns proposing work, choosing goals and pursuing them over time while remaining responsive to the person and the environment.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Goal | A represented outcome to pursue | Organises further work | Completing a substep is different from completing the goal |
| Initiative | A proposed action or task | Can enter selection or governance | A proposal can be refused or deferred |
| Priority | Relative importance under a stated rule | Determines which work is considered next | A high priority does not bypass a required permission |
| Outcome | What was observed after acting | Feeds completion and learning decisions | A successful tool call need not mean the real task succeeded |

## Governance

Governance checks whether a proposed action is allowed and records the decision and relevant evidence.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Capability | A scoped authorisation or declared ability, depending on context | Must be read with its scope | A token for one file is not unrestricted file access |
| Receipt | A structured record of a decision or effect | Makes actions inspectable | Transport success and independently measured outcome may differ |
| Authority | The rule or actor entitled to make a decision | Defines who can permit a consequence | A generated plan cannot grant itself new authority |
| Fail closed | Refuse or withhold when required evidence is absent | Prevents an unknown from silently becoming permission | A missing verifier is not a passing verifier |

## Resources

Resource management keeps model inference, background work and the operating system within the machine’s real capacity.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| RSS | Memory resident for a process | Shows part of its current memory footprint | Adding process RSS can double-count shared memory |
| Wired memory | Memory the operating system cannot page out in the ordinary way | Reduces room available for other work | Unified CPU/GPU allocation is not described by Python heap alone |
| Latency | Elapsed time for a defined step | Measures delay experienced by a user or pipeline | State the start and end points, not just one undifferentiated speed number |
| Throughput | Work completed per unit time | Describes sustained capacity | High tokens per second can coexist with a long startup delay |
| Backpressure | A request to slow or yield when a consumer cannot keep up | Limits queues and competing work | An expected yield should not automatically be reported as a dead system |
| GB and GiB | Decimal and binary memory units: 1 GB is 1,000,000,000 bytes; 1 GiB is 1,073,741,824 bytes | Different tools can describe the same capacity with different numbers | 64 GiB is about 68.7 GB; it is not extra newly available memory |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#resources) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#runtime)

## Reliability

Reliability work detects failed or stalled components, preserves useful state and recovers through a controlled lifecycle.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Liveness | Whether a component is still making the required kind of progress | Helps distinguish stalled from merely slow | A heartbeat alone may not show that a request is advancing |
| Readiness | Whether it can currently accept its intended work | Protects callers during startup or degradation | A living process can remain unready |
| Checkpoint | Saved state for continuing work | Can limit lost progress after interruption | Its presence does not prove that restoration has been tested |
| Timeout | A declared waiting limit | Bounds a stalled operation | An overly short limit can discard correct slow work |
| Taint | A retained record that an assumption or invariant broke | Keeps later green reports from concealing earlier damage | A repaired symptom does not automatically clear the historical condition |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#reliability) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#runtime)

## Observability

Observability records what the system did, how long each stage took, and where an assumption failed.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Metric | A declared numerical measurement | Supports comparison over time | Its unit, scope and missing-value behavior matter |
| Trace | Related events along one operation | Connects stages and delays | A request identifier prevents mixing two users’ turns |
| Log | A recorded event or message | Retains context for diagnosis | A message saying success is weaker than a verified outcome |
| Artifact | A retained output used as evidence | Allows later inspection or reproduction | A filename does not prove that the file contains measured data |
| Hash | A fingerprint of specified bytes | Detects a changed file relative to a recorded digest | It does not establish that the original contents were correct |

## Security

Security describes what information may cross a boundary and what untrusted input is allowed to influence.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Trust boundary | A point where data or authority changes scope | Defines which checks are required | A local browser page can still be untrusted input |
| Prompt injection | Content trying to redirect the assistant’s instructions | Must not acquire the authority of the person’s request | A downloaded document can contain adversarial instructions |
| Credential | A secret or token used to authenticate access | Must be handled within its authorised scope | A token name in documentation is not the secret value |
| Permission | A rule authorising a defined action | Limits consequences | Access to read does not imply authority to publish |

## Browser

Computer-use work observes an interface, chooses an action, and checks whether that action moved the task toward its goal.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Observation | The interface information actually read | Constrains what the agent can infer | An old screenshot may no longer describe the page |
| Target | The intended control or object | Binds the chosen action to a referent | Two similar buttons need a way to distinguish them |
| Action | A click, key or other interface operation | Attempts a state change | A dispatched action can fail to affect the intended object |
| Feedback | The observed consequence | Checks whether the action worked | A changed page is evidence; a tool returning success is only one signal |

## Physical

A physical-effect claim needs an independently observed change outside the program, compared with the relevant baseline.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Observable | The quantity to be measured | Defines what success would change | Temperature requires a declared sensor and unit |
| Channel | The route intended to produce an effect | Connects a request with a possible action | A declared channel can still be unavailable |
| Baseline | The comparison without the proposed effect | Separates the result from ordinary variation | A warm room can heat a sensor without the device’s contribution |
| Effect receipt | A record of independent post-action measurement | Supports a scoped outcome claim | It is stronger than a transport acknowledgement |

## Measurement

A test makes a specific claim answerable by a stated measurement, comparison and decision rule.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Control | A comparison that reveals another explanation | Can expose effects of the measuring procedure | An unchanged copy should not look like a deliberate intervention |
| Ablation | Disable a component for comparison | Asks whether that component matters to the outcome | A quality loss after removal can support a bounded causal claim |
| Effect size | How much a measured quantity changed | Shows practical magnitude | Statistical significance alone does not state a useful improvement |
| Coverage | What cases or paths were actually checked | Limits generalisation | An offline unit test does not cover a production microphone |
| Unmeasured | The required observation is absent | Prevents missing evidence from becoming a pass | A probe that cannot run contributes no positive score |

## ISC

ISC asks whether Aura’s measured parts form one continuing process under controlled changes, rather than merely having convincing descriptions.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Core | The selected group of measured state | Defines the proposed process boundary | Useful internal causes outside it can make the description incomplete |
| Carrier | The process proposed to carry the state being studied | Must be identified by the carrier experiment | A name or a passing synergy statistic does not select it |
| Synergy | A joint effect beyond adding the separate effects | Checks dependence of one source’s effect on another | The detailed guide works through 19 - 12 - 13 + 10 |
| Closure | Whether the proposed boundary omits an important internal driver after declared input is accounted for | Can remain unresolved rather than pass by default | No margin is currently in force; the earlier least-domain rule was withdrawn |
| Parity | The project’s five-ground bridge conjunction under named assumptions | Organises supporting evidence | It is not an independently calibrated probability of experience |

## Numbers

Symbols are shorthand for quantities whose definitions belong beside them. The same letter can mean different things in different parts of the project.

| Variable or term | Accessible definition | What it means in practice | Example |
|---|---|---|---|
| Vector, x or h | A list of numbers used to represent a state | Different coordinates can describe different properties | A two-value example could keep condition and urgency; real model coordinates need their own interpretation |
| Matrix, often W | A table of numbers used in a transformation | Can map one numerical representation to another | In the ISC domain labels, W instead means world model |
| Delta, Δ | A change or configured intervention | Shows a difference rather than an absolute level | Going from 10 to 13 gives a change of +3 |
| Mean | The arithmetic average | Summarises a collection while hiding variation between its entries | Changes +1 and +5 have mean +3 |
| Spread or standard deviation, often sigma | How much values vary around a reference | Makes an intervention interpretable relative to ordinary variation | A change of 1 is large if ordinary variation is 0.1 and small if it is 10 |
| z score | Distance from a reference mean in units of its standard deviation | Describes above-usual or below-usual state under a defined reference | Value 12, mean 10 and spread 2 give z = +1 |
| p value | The extremeness of a statistic under the declared null comparison | Belongs to one test and its assumptions | It is not the probability of consciousness |
| q value | A multiple-testing-adjusted statistical quantity under its declared procedure | Helps control a stated error rate across many comparisons | Checking many candidate edges needs a declared family-level rule |
| rho | A correlation coefficient; ISC uses ranked comparisons in named analyses | Describes how two sets of values or changes vary together | High agreement does not by itself establish one caused the other |
| Epsilon or margin | A declared acceptable residual or error bound, depending on context | Defines the precision of a claim | An unnamed margin cannot be inferred from a convenient observed result |
| Lambda | A context-dependent coefficient or residual-control symbol | Must be read from the local definition | The same letter can mean a decay setting in one model and an outside-control quantity in another |
| Phi | A name used for several integration-related measurements | Its formula, state description and controls determine its meaning | Different phi implementations are not interchangeable consciousness meters |
| Expected value, EV | Expected benefit minus the relevant costs under a stated accounting | Helps decide whether a retained method is worth using | Benefit 5 and cost 7 give net value -2 |
| Fingerprint or digest | A hash of specified data or configuration | Detects that an input or file changed | Two different campaign fingerprints must not silently become one result |

[Why this matters, with a metaphor](PLAIN_ENGLISH_GUIDE.md#numbers) · [Demos and related work](DEMOS_AND_RELATED_WORK.md#measurement)

## Before interpreting a number

Ask what was measured, in which units, on which cases and under which controls. Check whether the value is missing, estimated or directly observed. A threshold passing is a statement about the declared test, not a general guarantee.

A larger value is not automatically better. More stored records can mean worse retrieval, more work can mean worse latency, and stronger coupling can mean less useful flexibility. The user-visible outcome needs its own measurement.
