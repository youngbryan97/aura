## Corrections that change the implementation decision

The printed temperature loss is `log(1 + exp(-margin / T_family))`.
For positive T, `sign(margin / T) == sign(margin)`. This transformation alone
cannot reverse an incorrect pair ordering or resolve contradictory fixed-score
sign requirements. Jointly learning the original coefficients can change their
ordering, but the report supplies no proof that four temperatures solve the
current problem. It also does not define a deployable family for a mixed
multi-operation graph. There is no evidence for its proposed [0.3, 3.0] bounds.
Keep calibration as a source-fold experiment; do not install it as a guaranteed
repair or introduce a family oracle.

The first-feasible selector can learn: it sorts scores emitted by learned
operation heads, then selects arguments. Its lexicographic policy does not
freeze those coefficients. The source-level policy comparison measures the
particular four arms, not impossibility of learning under that policy.

The proposed cache sorts input values. That aliases `sub(8,2)=6` with
`sub(2,8)=-6`, and `idiv(8,2)=4` with `idiv(2,8)=0`. New regression tests
preserve the shipped cache's ordered input key and distinct input receipts.
Alpha-renaming must transport the input mapping; it must not erase it.
Canonical equivalence of outputs also does not imply equal fuel usage or
identical provenance receipts. Cross-request reuse may share a pure result,
but must bind each new request's evidence instead of copying old attribution.

Static primitive type validation already happens in `_compile_body` before
floor execution, for both source IR and source-independent procedures. The
existing ill-typed-intermediate test verifies that boundary. Therefore the
claimed missing type pass and automatic two-million-step saving are incorrect.

Definition evidence counted once is not the same as allowing each definition
to be used only once. The existing test repeats a definition in both arguments
and counts its attachment evidence once. A universal at-most-once restriction
would incorrectly exclude `x*x` and `x-x`. Use constraints must come from the
declared task grammar, not this report's blanket restriction.

`ProcedureRegistry.match` already filters `signature.matches(state)` before
value ranking. The proposed precondition repair duplicates that behavior.
Grounding user intent into those task requirements is a separate open problem.
Evidence packets must not upgrade a successful execution to verified truth.

The report's G07/G08 "not started" status misses existing preregistration,
power, source-identity and independent-verification infrastructure. Its N=384
and cluster-adjusted N=500 claims reuse the unsupported power calculation
documented in the preceding review. Candidate-specific discordance and cluster
structure must be measured before sizing confirmation.

The 492/500 threshold, two permitted regressions, 80-percent family floor,
50 decodes, 90-percent steering retention, 200-ms rollback and 20-turn serving
thresholds are not adopted as release policy. Named frontier versions, memory
assumptions, asserted scoring ranges and multi-day estimates need independent
verification. Reducing a beam because a solver takes 15 seconds would change
coverage; it cannot silently replace the current complete-search contract.
