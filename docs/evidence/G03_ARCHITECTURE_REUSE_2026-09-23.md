# G03 architecture reuse before another fit

The current role-binding misses are selection failures. The correct programs
are in the frozen bank. Two misses reverse their source-chart score margin
when the operation spans come from ordinary runtime charts. This record maps
existing architecture to that measured defect before another candidate fit.
It grants no serving authority.

The missing connection is between the decoder's runtime operation hypotheses
and the source-supervised argument head. The earlier selected-decode view
added 12 examples from 728 source examples and changed no held-out program.
`runtime_argument_training_views` now has an opt-in bounded chart mode. It
generates operation spans without a target, aligns only same-operation,
one-to-one overlapping charts to source training labels, remaps equal-valued
input registers by source anchor, and retains the original example. The
pairwise fitter balances all views of one source as one source observation.
The refit CLI exposes the chart allowance, coreferent-mention preservation,
and the existing full runtime mention objective together. This is a candidate-fitting path,
not a live answer selector or a result.

The separate complete-program ranker already has source-conditioned scoring,
candidate-set loss, and a source bank. It now has an opt-in identity-binding
term and source-bank runtime-chart factor training with one balanced update
per source. This addresses the proposals' role-identity and training/runtime
view gaps at the full-program selection level. Neither ranker extension nor
local-head refit has a new held-out result yet. The PDF review and remaining
experimental boundaries are recorded in
[G03 PDF architecture disposition](G03_PDF_ARCHITECTURE_DISPOSITION_2026-09-23.md).

Before any promotion: check chart-view coverage, verify that changed weights
reach the ordinary graph selector, run paired validation by construction,
preserve an untouched test, and compare with the incumbent on fresh transfer.
