# Retaining unresolved program distinctions

The semantic portfolio can retain its discriminating inquiries through the
existing StateGateway. Planning runs off the event loop; writes use the
gateway's asynchronous durable mutation and receipt path. There is no new
storage engine or model prompt.

Each pending inquiry carries its probe, program identities, predictions and
information score. Reload validates those bindings. A stored pending inquiry
cannot claim an observed answer or correctness authority. Reopening a real
ConcreteStateGateway in tests recovers the inquiry and allows comparison with
a subsequently supplied value. Missing records remain missing.

This preserves pending distinctions for a caller that retains their identities.
Desktop delivery, durable observed-answer revision, and live cross-turn reuse
are still separate integration work. No G checkpoint is closed by persistence
alone. The first validation run rejected native prefixed program hashes;
the validator was corrected to use the actual `Program.sha()` contract.
