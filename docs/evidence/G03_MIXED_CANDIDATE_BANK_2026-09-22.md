# Mixed candidate bank on the exposed development misses

The source-bound audit regenerated a candidate bank for every one of the 23
failures in the frozen 500-task development portfolio. It used the exact
literal-identity transducer named by its candidate report, the frozen source
feature manifests, and the independently retained contextual graph proposals.
The target program was admitted only after generation and coordinate alignment.

| Observation | Count |
| --- | ---: |
| Previously missing from both top-one methods | 14 |
| Previously available but not selected | 9 |
| Correct program found in the literal decoder's retained bank | 23/23 |
| Correct program selected by ordinary decode | 0/23 |
| Mixed union with a correct program | 23/23 |
| Additional correct cases from same-position composition | 0/23 |
| Exhausted complete declared search | 0/23 |

Each bank retained 33 candidates: the ordinary answer and at most eight
operation charts with four argument graphs each. The first equivalent program
appeared between bank indices one and twelve. Every row reported incomplete
search because the finite chart/graph allowances were reached; two also had
an interrupted graph solve. A witnessed correct candidate is valid despite
incomplete enumeration. Absence would not have proved unreachability.

The old `candidate_unavailable` label meant unavailable from two top-one
programs. It did not mean the typed grammar could not express the answer.
This audit localizes all 23 exposed misses to selection within a reachable
bank. It does not show that one score rule can select correctly, nor that
the same coverage holds for fresh requests or other families. The correct
program was not installed as a fallback, and the bank has no serving
authority. G03 remains open.
