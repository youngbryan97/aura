## Research used

[BehaviorTree.CPP sequences](https://www.behaviortree.dev/docs/nodes-library/SequenceNode/)
distinguish remembered successful steps from reactive conditions and yield between
asynchronous steps so conditions can be checked again. This informed retained
obligations and verification between inputs; no new parallel task executor was
added.

[Real-Time Execution of Action Chunking Flow Policies](https://arxiv.org/abs/2506.07339)
separates actions committed to execution from future actions being computed. Its
flow-policy algorithm is not a drop-in for this runtime. This checkpoint adopts
explicit dispatch ownership and observation timing; it does not claim the paper's
robotics performance or install a trained policy.

The implementation uses object geometry, measured appearance, temporal custody
and required effects without game names or game-specific success formulas.
