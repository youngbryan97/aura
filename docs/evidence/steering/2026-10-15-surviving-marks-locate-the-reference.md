# Surviving marks locate the reference — 15 October 2026

The first exact-frame CPU recording at `4f7040fb4` retained 47 frames and
16 input events, with no queue drops or storage errors. Original case 18
again reported zero landings and one crash. This was the direct browser
play path, with software graphics, CPU OCR and auxiliary model workers
refused. It was not a native Aura prompt or a witnessed win.

Pixel-only replay retained the moving body's track for 42 observations;
27 had accepted motion. Several reference losses occurred despite nine
or more surviving original marks: a fixed 60 percent anchor-retention
condition rejected them before rigid fitting. The physical inputs were
three thrust holds and one lateral hold before the terminal screen.

The reference now requires at least three original named marks, the existing
noncollinear rigid-consensus fit and agreement with the current local
motion. It also carries an accumulated RMS precision estimate at the retained
origin. That estimate includes raster resolution, fit residual, point spread
and the distance from the marks to the origin. Exceeding one working pixel
ends the reference. The 60 percent check is replaced by that geometric
qualification. New marks still join only through an accepted transform;
unbridged replacement, deformation and collinearity remain failures.

This is an engineering use of first-order target-registration geometry,
informed by [Danilchenko and Fitzpatrick's error analysis](https://pmc.ncbi.nlm.nih.gov/articles/PMC4607070/).
The implemented two-dimensional estimate is not their full covariance model
and does not bound correlated tracking errors or guarantee object identity.
The causal identity gates were not changed.

Replaying the same pixels after this change raised the moving track's
accepted observations from 27 to 32 of 42. That is a perception measurement;
it does not establish control or improve the game's outcome by itself.
Across all tracks, accepted observations changed from 473 to 477; association
can change when a continuing reference affects the next matching proposal.

The replay tool verifies pixel hashes and retains point-handoff diagnostics.
The opt-in recorder can also retain the actor's actual independent flags,
press sample counts, push counts and identity selection, separately from
replayed observations. This will locate any remaining failure between
measured material and the control witness.

Validation so far: 85 focused tests passed, including existing reference,
replacement, rotating-point and birth-custody counterexamples. Twenty tests
passed after adding replay hash and actual control-count coverage. An initial
new rotation test used a mask that excluded its rotated marks; its fixture
now follows the transformed object. No production support rule was weakened
to make that test pass. Broader gates and a fresh CPU play run follow.
