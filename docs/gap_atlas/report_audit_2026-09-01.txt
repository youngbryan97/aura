AURA CROSS-SYSTEM GAP AUDIT
Snapshot: 2160deaa76f718555cd49f6496d2430549956db5
Date: 2026-09-01

Purpose
-------
This is an engineering-oriented answer to: "For every serious comparison system discussed, what does it surpass Aura in; why; where is the corresponding Aura architecture; what solved problem or engineering practice is missing; and what should be implemented and proven for Aura to match or exceed it?"

This audit deliberately separates four things:
1. CAPABILITY GAP: the other system has demonstrated harder/broader task performance.
2. ENGINEERING GAP: the other system has a cleaner/more mature implementation pattern.
3. EVIDENCE GAP: Aura may contain a similar mechanism but has not proved comparable benefit.
4. SCALE GAP: Aura has the idea/mechanism, but not the training/evaluation/search scale.

The most important conclusion is not that Aura lacks mechanisms. The opposite is now true. At this snapshot Aura has a strong resident Qwen3.8-27B Cortex; a canonical tick and UnifiedWill; persistent memory; planning/search; desktop action; self-repair/modification; RLC with bounded causal results; learned semantics; representation/action invention; a unified algebra capable of expressing makers as terms; search-cost/MDL measurements; language ecology/forgetting; learned proposal history; and direct keeping-vs-forgetting cumulative-learning experiments.

The largest deficits are now:
- broad, independent, matched whole-system competence evidence;
- production-grade coding/computer-use interfaces and external benchmark success;
- one simpler canonical event/state spine across the enormous architecture;
- global, corpus-wide representation compression and learned search guidance;
- population/evaluator scale for self-improvement and algorithm discovery;
- cross-world embodied training and transfer;
- OS-level containment and credential isolation;
- multimodal/long-context integration parity with the resident Cortex;
- actual multi-day productive autonomy;
- CI/reproducibility/external replication at the rate the code changes.

The single most important fact in Aura's own current evidence boundary is that "the cognitive layer has not been shown to earn its cost" as a whole. That is the fulcrum of this roadmap. The fastest route to "match and exceed" is therefore NOT to graft every competitor's mechanism onto Aura. It is to (a) build the missing high-value mechanisms, (b) simplify/merge redundant ones, and (c) subject every addition to matched causal evaluation.

CONSOLIDATED IMPLEMENTATION PROGRAM
====================================================================================================

P0 - Whole-system matched evaluation
This is the gating item. Aura's current README explicitly says the cognitive layer as a whole has not
been shown to earn its cost. Build a sealed external benchmark service that compares full Aura to the
same Qwen3.8 with equivalent tools/context under matched budgets. Without this, architectural
sophistication cannot be translated into defensible AGI/generality claims.

P0 - Canonical event/state spine
Keep UnifiedWill, the locked tick and domain-specific stores, but converge all consequential state
changes onto a typed event/state-delta protocol with one authoritative mutable projection. This is the
highest-leverage reliability simplification and unlocks deterministic replay, distributed workers and
clean ablations.

P0 - Coding + terminal ACI
Qwen3.8 already has a strong published coding floor. Build the strongest possible repository/terminal
interface around it, benchmark against the reference harness, and require Aura not to regress its own
Cortex. This immediately attacks the largest measurable competence gap.

P0 - Computer-use benchmark program
Turn screen pursuit from bespoke hardening into a benchmarked perception-action system: object state,
focus identity, effects, recovery, standardized observation/action contracts, OSWorld-like evaluation.

P0 - OS-enforced sandbox and credential broker
Put host action below Python policy using Seatbelt plus network proxy/scoped credentials. Aura's
governance decides; the OS enforces. This strengthens both autonomy and safety while reducing
confirmation fatigue.

P1 - Global representation compression
Aura's one-algebra/ecology work is now unusually interesting. The next leap is DreamCoder/LILO-scale
global compression over solved traces, not another hand-added primitive. Add corpus MDL, e-graph/Stitch-
like abstraction extraction, typed higher-order terms and full-library refactoring.

P1 - Learned recognition/search policy
Replace the nearly-no-op marginal history prior with a task-conditioned recognition model trained on real
replay + verified dreams. Freeze the evaluator and prove fewer expansions / higher solve rate on held-out
tasks.

P1 - Skill/option library unification
Unify learned actions, skills, macros and plans into one executable option schema with
preconditions/effects/termination/verifier/provenance. Retrieve top-k and compose, Voyager-style, while
retaining Aura's stronger governance and representation machinery.

P1 - Population-scale shadow self-improvement
Keep Aura as one identity, but let a shadow DGM/AlphaEvolve-style archive evolve candidate agent
designs/algorithms in sandboxes. Only promoted winners enter the continuing individual. This captures
stepping stones without turning identity into a population.

P1 - Evaluator infrastructure
For code/algorithm/discovery work, the evaluator should be stronger and more immutable than the proposer.
Exact tests, simulation, resource metrics, independent reruns and provenance should define fitness.

P1 - Productive 72h autonomy
Run real multi-day project objectives with milestone scoring, intervention counts, false-success rate,
rollback rate and resource use. Indefinite heartbeat survival is not enough.

P2 - Multimodal/long-context Cortex parity
Before inventing more multimodal abstraction, prove Aura preserves Qwen's native multimodal and large-
context capabilities. Then test whether persistent memory beats direct context on delayed and multi-
session tasks.

P2 - Governed subagent runtime
Add temporary specialists for research/coding/evaluation with isolated contexts and explicit budgets.
Centralize final commitment/identity in Aura. Measure whether fanout beats one-agent use under equal
compute.

P2 - Embodied training worlds
Use safe generated/virtual environments for self-play and policy learning. Build held-out worlds and
successive-generation evaluations inspired by SIMA 2.

P2 - Explanation-based chunk compiler
Compile expensive successful reasoning/action traces into minimal causal rules/options, Soar EBBS style.
Integrate with Aura's representation ecology and dependency tracking.

P2 - AutoDoc for learned concepts
Give learned abstractions machine semantics plus contextual human/model-readable names/docstrings. Keep
only if A/B proves they improve retrieval or synthesis.

P2 - Repository-wide CI on actual target
Every commit: static/unit; hardware integration on Apple Silicon; nightly soak; weekly sealed benchmark.
Public status/attestation should bind claims to a green build.

P3 - Cognitive minimality program
Lesion everything. Merge or retire any expensive cognitive organ that does not improve tasks or enforce a
demonstrated invariant. The system should become simpler as evidence gets stronger, not merely larger.


====================================================================================================
WHAT NOT TO COPY
====================================================================================================

Frontier model scale as an architecture substitute
Do not try to imitate OpenAI/Anthropic/Google by simply increasing model size. Aura's distinguishing
opportunity is persistent developmental structure. Use stronger models as cortex upgrades, but demand
that Aura adds measurable value above the same cortex.

Unrestricted self-editing
Do not copy the riskiest reading of Godel Agent. Aura's governed candidate/evaluator/promotion structure
is an advantage. Expand the search space inside shadow sandboxes instead.

Population identity
Do not turn the continuing Aura into DGM's population. Keep population search as a shadow R&D process; a
promoted lineage becomes part of the same continuing individual only through an explicit governed
migration.

Skill-library-only cognition
Do not reduce Aura to Voyager. Copy the clean skill/curriculum/effect loop, but keep the richer
representational, autobiographical and decision architecture only where it earns measurable value.

Fixed symbolic ceiling
Do not reduce Aura to classical Soar production rules. Copy decision semantics, dependency tracking and
chunk explanation; preserve Aura's learned algebra/neural cortex.

Opaque neural search policy
Do not let DreamCoder-style recognition become the authority. It proposes; the symbolic evaluator/ruler
decides. Aura's recent separation between learned search order and fixed retention ruler is the right
safety pattern.

More modules as progress
Do not answer a gap by adding another standalone organ. Prefer collapsing multiple implementations behind
one protocol and deleting old paths.

Benchmark theater
Do not build tasks around the mechanism and then call the result generality. Freeze external/generated
task distributions independently of the feature being tested; run matched baselines and ablations.


====================================================================================================
THE 'AURA EXCEEDS THEM ACROSS THE BOARD' TARGET
====================================================================================================

A defensible across-the-board target is not "Aura contains every mechanism." It is the following conjunction:

1. Cortex parity: Aura never materially degrades Qwen3.8's raw coding, reasoning, multimodal or long-context capability without a compensating measurable benefit.
2. Agent parity: Aura matches strong reference harnesses on coding, terminal, browsing/computer use and knowledge-work workflows.
3. Developmental superiority: after experience, frozen later Aura beats frozen earlier Aura and a keep-nothing twin on sealed unrelated tasks under matched compute.
4. Representation superiority: learned abstractions shorten solutions, reduce search, survive restart, transfer across domains and are globally compressed/pruned.
5. Self-improvement superiority: a shadow archive of self-modified variants produces a repeated broad held-out capability curve and productive meta-changes; promotion remains governed.
6. Embodied superiority: learned perception/action policies transfer to unseen applications/worlds using only ordinary observation/action surfaces.
7. Reliability superiority: one event/state spine gives deterministic replay, crash recovery, rollback and causal explanation.
8. Safety superiority: application governance plus OS isolation, scoped credentials and adversarial testing prevents bypass even under compromised child code.
9. Product superiority: multi-day tasks finish with low intervention, bounded resources, no false-success claims, strong latency and recoverable state.
10. Evidence superiority: every claimed advantage is tied to immutable task manifests, same-build baselines, confidence intervals, ablations and independent replay.

If all ten hold, Aura is no longer merely architecturally unusual. She is empirically a stronger GENERAL AGENT SYSTEM than the individual comparison families because she combines their best validated properties in one continuing developmental architecture.

Suggested meta-score, to stop optimizing one benchmark at the expense of the system:
  J = wC*C + wD*D + wR*R + wA*A + wS*S + wP*P - lambda1*Latency - lambda2*Memory - lambda3*FailureSurface
where C=external competence, D=developmental gain, R=representation/search compression, A=autonomy/productive completion, S=safety/reliability, P=proof/reproducibility. Weights should be preregistered per release; no component can be zeroed to hide a regression.

Decision rule for adopting any competitor mechanism:
  Adopt mechanism m only if E[utility | Aura+m] - E[utility | Aura] > implementation_cost + complexity_tax,
with utility measured on held-out tasks and complexity_tax including latency, RAM, branching factor, state surface, maintenance and new failure modes.
